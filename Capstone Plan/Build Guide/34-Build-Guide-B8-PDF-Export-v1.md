**Depends on:** nothing new — reuses `app/export.py`'s existing text builder.

## Goal in plain language

The Export tab already offers a copyable text block and a **Download (.md)** file.
A PDF is the format a non-technical stakeholder (the founder our personas
describe) can actually forward to a colleague or drop into a board pack. Same
content, more shareable container. **No new data, no new pipeline logic** — it's a
render of the blueprint the user already has on screen.

## Why this is low-risk (and where the risk actually is)

- The content already exists: `blueprint_to_text(result)` in `app/export.py`
  produces the exact plain-text blueprint used by the copy block.
- No network call, no new user input, no telemetry field beyond one event name —
  so it doesn't reopen any Week-3 data-minimisation finding (Card P.4).
- **The real risk is dependency/deployment**, not code. See step 1.

## Step 1 — Choose the library (decision, then `requirements.txt`)

Recommended: **`fpdf2`** (`pip install fpdf2`, imported as `from fpdf import FPDF`).

| Option | Why / why not |
|---|---|
| **`fpdf2`** ✅ | Pure Python, no system libraries, tiny, works on Streamlit Community Cloud. Enough for a text-layout document like ours. |
| `reportlab` | Also pure Python and very capable, but a heavier API for what is essentially monospaced text on a page. |
| `weasyprint` | Best HTML→PDF fidelity, but needs system libs (cairo/pango) — likely to break a cloud deploy. **Avoid for this MVP.** |

Add to `requirements.txt` (alphabetically near the top, next to `pandas`):

```
fpdf2
```

## Step 2 — Add the PDF builder to `app/export.py`

Add a third function alongside `blueprint_to_text()` and `blueprint_to_markdown()`.
Return **bytes**, because `st.download_button` needs bytes for a binary file.

```python
def blueprint_to_pdf(result: dict) -> bytes:
    """
    Icebox B.8 — render the blueprint as a simple, shareable PDF.
    Deliberately a plain monospaced text layout: same content as
    blueprint_to_text(), just in a container a stakeholder can forward.
    Returns raw PDF bytes for st.download_button.
    """
    from fpdf import FPDF  # local import: keeps app start-up fast if unused

    text = blueprint_to_text(result)

    pdf = FPDF(format="A4", unit="mm")
    pdf.set_auto_page_break(auto=True, margin=15)
    pdf.add_page()
    pdf.set_margins(15, 15, 15)

    # Title line
    pdf.set_font("Helvetica", "B", 14)
    pdf.multi_cell(0, 8, result.get("project_name") or "Your AI Stack Blueprint")
    pdf.ln(2)

    # Body — Courier keeps the ranked list / cost columns aligned like the
    # on-screen code block.
    pdf.set_font("Courier", size=9)
    for line in text.split("\n"):
        pdf.multi_cell(0, 4.5, line if line.strip() else " ")

    # Footer disclaimer — must stay, it mirrors the in-app honesty line.
    pdf.ln(4)
    pdf.set_font("Helvetica", "I", 8)
    pdf.multi_cell(0, 4,
        "Directional only. Pricing is illustrative and may be out of date; "
        "compliance filtering is a shortlist, not certification. "
        "Generated by AASA, a 4-week student prototype.")

    return bytes(pdf.output())
```

**Character-encoding caveat (test this first).** `fpdf2`'s built-in fonts are
Latin-1/cp1252 — our blueprint contains **€**, **·** and **em-dashes**. If any of
those raise a `UnicodeEncodeError` or render as garbage, pick one fix:

1. Sanitise in the PDF path only — e.g. replace `€` with `EUR `, `·` with `-`,
   `—` with `-` before writing (simplest, keeps the .md/text exports untouched).
2. Or embed a real TTF: `pdf.add_font("DejaVu", "", "path/to/DejaVuSansMono.ttf")`.
   **Note:** our `static/fonts/` files are `.woff2`, which fpdf2 **cannot** use —
   you'd need to add a `.ttf`, which means a new vendored binary + a licence
   check. Only do this if option 1 looks bad.

## Step 3 — Wire the download button in `app/dashboard.py`

In `_render_action_row()` the four columns are currently
Save / Download (.md) / .env scaffold / Blueprint copied ✓. **Don't add a fifth
column** — at the sidebar-open width the labels already sit close together.
Instead put the PDF button *underneath* the row, or convert col1 into a small
"Download" popover holding both `.md` and `.pdf`. Recommended (least layout risk):

```python
        if st.download_button(
            "Download (.pdf)",
            blueprint_to_pdf(result),
            file_name="aasa-blueprint.pdf",
            mime="application/pdf",
        ):
            log_event("pdf_downloaded")
```

Also add the import at the top of `app/dashboard.py`:

```python
from app.export import blueprint_to_text, blueprint_to_markdown, blueprint_to_pdf
```

**Performance note:** `blueprint_to_pdf()` runs on *every* rerun because
`st.download_button` needs its data up-front. It's a small document so this is
fine, but if the Export tab ever feels sluggish, wrap it in `@st.cache_data`
keyed on the result.
